# 会议记录模板

> 用途：本文件是「会议记录归档」的标准模板。生成文档时用实际数据替换 `{{占位符}}`，并严格遵守下方的格式规范。标「可选」的区块若无数据可省略，并在汇报中说明。
>
> 模板里的 `{{@姓名}}` 是人名写法：有 Outline 账号的写提及 `@[姓名](mention://user/<userId>)`，没有账号的写纯文本 `@姓名`，没确认的匿名标签原样写「发言人N」（SKILL.md 第三节「人名一律 @」）。

## 命名规则

目录结构（两级，没有日期目录）：

```
会议纪要/
├── YYYY-MM-DD 会议主题 HH:MM         ← 同一天同名的另一场，加实际开始时间
└── YYYY-MM-DD 会议主题               ← 实际开会日期 + 会议名
```

示例：`2026-09-15 产品周会`；同一天第二场：`2026-09-15 产品周会 16:30`

- 文档标题的主题取 meeting get 的 subject（会议名字）；只是会议室默认名时改用智能纪要的会议主题
- 文档头部的「会议主题」字段写智能纪要给出的主题名
- 实际起止时间写在「会议时间」字段里，标题里不再写时间段
- 新的在上

## 格式规范速查

| 元素 | 语法 |
| --- | --- |
| 高亮 | `==文字==` |
| 加粗 | `**文字**` |
| 斜体 | `*文字*` |
| 行内代码 | `` `代码` `` |
| 引用块 | `> 文字`（多行引用每行一个 `>`） |
| 水平分隔线 | `---` |
| 无序列表 | `- 项目`（项与项之间加空行） |
| 表格 | markdown 表格 |
| 提及（有账号） | `@[姓名](mention://user/<userId>)`，userId 用 `list_users` 查 |
| 人名（没有账号） | 纯文本 `@姓名`，后面紧跟文字时空一格 |

## 注意事项

- 没有数据的内容不要编造，标注「未获取」
- 人名一律 @：没匹配上、拿不准的名字（包括同音字）和匿名发言人，写入前一次问用户，不猜
- 「纪要整理」写 current_user，不是主持人
- 转写段落多时（几十段），用脚本解析 CLI 的 JSON 输出，避免手抄出错
- 高亮要克制：风险、时间节点、关键决策才高亮，不要整段全亮
- 转写原话保持原样，包括口语化表达和语气词，不要润色
