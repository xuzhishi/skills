# 会议记录归档（腾讯会议 → Outline）

## 概述

本 skill 把"将一场腾讯会议的记录整理并写入 Outline"的完整流程标准化：

1. **环境自检（强依赖）**：tmeet CLI、tmeet-skill、tmeet 登录、Outline MCP、Outline token——五项全部就绪才继续，缺哪项就必须先补齐哪项
2. **拉取数据**：会议基本信息、智能纪要、待办、参会明细、逐字转写
3. **组装文档**：按 `references/template.md` 的结构与格式规范生成；人名一律 @，基本信息里写明纪要整理人（Outline token 的主人）和整理时间
4. **写入 Outline**：定位「会议纪要」（用户指定的文档集或项目，否则默认个人文档集），直接在它下面创建「YYYY-MM-DD 会议主题」，新的在上；在项目下时，「会议纪要」排在看板、进度与待办、项目文档之后

每个环节的数据（会议号、用户名、文档集、token）都是运行时动态获取的，本 skill 不内置任何固定的值。

## 一、环境自检（强依赖，全部就绪才继续）

以下五项是本工作流的**硬性前置条件**：缺了它们既拿不到会议数据，也没地方写文档。任何一项不满足，流程就停在这一步，先把环境补齐，补齐后从头继续。

### 1. tmeet CLI（强依赖）

- 检查：`command -v tmeet`
- **`command -v tmeet` 找不到、但用户说已装过**：tmeet 可能装在 nvm/fnm 等 Node 版本管理器下（PATH 未覆盖）。先查 `ls ~/.nvm/versions/node/*/bin/tmeet ~/.fnm/*/installation/bin/tmeet 2>/dev/null`，找到后用其**绝对路径**调用，无需重装
- 未安装：执行 `npm install -g @tencentcloud/tmeet@latest`（若被环境策略拦截全局安装，改走 Cherry 托管 CLI：`cli_search` 搜不到 tmeet 时，用 `cli_install` 装 `npm:@tencentcloud/tmeet`）
- 若 node/npm 也不存在：告知用户先安装 Node.js LTS（nodejs.org），装好后再继续
- 安装失败：把报错原文展示给用户，检查网络或 npm 源后重试

### 2. tmeet-skill（强依赖）

- 检查：当前会话的可用 skills 列表里是否有 `tmeet-skill`（腾讯会议 CLI 技能）
- 没有：通过技能市场搜索「腾讯会议」并安装（`install_skill`），先征得用户同意再执行
- 原因：tmeet-skill 的 `references/` 里有全部 tmeet 命令的完整参数、路由规则与错误码，是本 skill 拉取会议数据的操作手册，必须存在

### 3. tmeet 登录（强依赖）

- 检查：`tmeet auth status`
- 未登录（提示 `user config is empty`）：必须引导用户完成 `tmeet auth login` OAuth 授权，**登录成功后才能继续**
  - 这是阻塞命令：输出授权 URL 后等待用户在浏览器完成 OAuth（最长约 5 分钟）
  - 必须前台运行，不要加 `&` 后台执行，否则回调无法写入凭证
- 登录成功后记住 `UserName`——后面定位"默认个人文档集"要用

### 4. Outline MCP（强依赖）

- 检查：调用 Outline MCP 的 `list_collections`（不带参数）
- **工具不存在**（调用即报工具不可用）→ Outline MCP 未安装或未启用，必须装上：
  1. 向用户说明缺少什么
  2. 请用户提供：Outline 服务地址（如 `https://outline.公司域名`）+ 个人访问 token（Outline 里「设置 → API → 创建 token」）
  3. 引导用户在 Cherry Studio「设置 → MCP」添加 Outline MCP server；在支持注册工具的环境里，征求用户同意后帮其注册
- **工具存在但调用报错**：
  - 401 / 认证类错误 → token 无效或过期，必须让用户更新 token 后才能继续
  - 连接超时 / 拒绝 → 服务地址不可达，检查地址与网络，恢复后才能继续

### 5. Outline token（强依赖）

- 无 token 或 token 无效时（表现为 401），向用户说明获取方式：Outline「设置 → API → 创建个人访问 token」
- 校验通过标志：`list_collections` 成功返回——至此环境自检全部通过，进入拉取数据阶段
- 接着调用 `fetch`（resource=user，id=current_user），记下返回的姓名和 id：这就是 MCP 里这个 Outline token 的主人，也就是本次的**纪要整理人**（常常是产品经理，不一定是主持人）。不要拿主持人或 tmeet 的 `UserName` 顶替；取不到时问用户是谁在整理

## 二、拉取会议数据

### 定位会议

| 用户提供的信息 | 使用命令 |
| --- | --- |
| 会议号（如 `123 456 789`） | `tmeet meeting get --meeting-code "123456789"`（去掉空格与横线，纯数字） |
| 主题 / 关键词 | `tmeet meeting search --query "关键词" --query-field subject` |
| 只有日期 | `tmeet meeting list-ended --start "YYYY-MM-DDT00:00:00+08:00" --end "YYYY-MM-DDT23:59:59+08:00"` |

- 返回多场候选 → 用表格列出（会议号、主题、时间）让用户确认，不要擅自替用户选
- `meeting get` 成功后获得：主题、起止时间、会议号、会议类型、主持人、入会链接、录制列表（含 `permission_status`）、子会议列表（周期性会议）
- **⚠️ Rooms 会议室会议 / 个人会议号会议（特殊场景）**：`meeting get --meeting-code` 会返回「个人会议号会议」的固定条目（subject 常为「XXX的个人会议室」、status 常为「待开始」、无录制无纪要），**这不是实际会议**。此时改走 `record search --meeting-code` 定位实际录制（拿到实际 `meeting_id`、`record_file_id`、录制起止、`has_smart_minutes`/`has_transcript_content`）；真实会议主题取智能纪要的「会议主题」字段；`report participants` 对 Rooms 会议通常 9042 无权限，参会明细标注「未获取」

### 拉取内容（三类数据都要拉）

1. **智能纪要**：`tmeet record smart-minutes --record-file-id <record_file_id>`
   - 前置条件：该录制的 `permission_status = can_view`（用主录制，通常时长最长）
   - 无权限或无录制 → 降级 `tmeet minute get --meeting-code <code>` 取元宝纪要，并在最终文档与汇报里明确标注"内容来自元宝纪要、非逐字稿"
2. **完整转写**：`tmeet record transcript-get --record-file-id <record_file_id>`
   - 输出可能是 100KB 级 JSON（含 paragraphs），**用 node/python 脚本解析**成"发言人 + 文本"再使用，不要手工抄录
3. **参会明细**：`tmeet report participants --meeting-id <meeting_id> --sub-meeting-id <首场子会议id>`
   - 周期性会议必须带上子会议 ID（`meeting get` 返回的 `sub_meetings[0].sub_meeting_id`）
   - 得到：总人次（含重复入会）、去重后的参会名单、入离会时间

### 参数与细节

- 拉取数据时按需查阅 `tmeet-skill` 的 `references/`（环境自检已保证其存在），里面是各命令的完整参数、路由规则与错误码说明
- 时间参数一律 ISO 8601 带时区，如 `2026-09-07T11:00:00+08:00`
- **会议号对外展示永远用 `meeting_code`；`meeting_id` 只作命令参数，严禁出现在任何面向用户的输出里**

## 三、组装文档

- 读取 `references/template.md`，按模板结构和格式规范生成文档
- 数据来源映射：
  | 区块 | 数据来源 |
  | --- | --- |
  | 基本信息（主题/时间/会议号/类型/主持人/入会链接/录制） | `meeting get` |
  | 会议摘要、会议内容、待办事项 | 智能纪要（`smart-minutes`） |
  | 关键风险点 | 从纪要内容归纳风险项（检测风险、时间紧迫项、未决事项） |
  | 下次会议 | `meeting get` 子会议列表的下一场 |
  | 参会统计、参会名单 | `report participants` |
  | 完整转写 | `transcript-get` |
  | 纪要整理 | 环境自检取到的 current_user + 写入前取的当前时间（`TZ=Asia/Shanghai date '+%Y-%m-%d %H:%M'`） |
- 两个容易用错字段的取数规则：
  - **会议时间**：写**实际**会议时间，不要用 `meeting get` 返回的预定 `start_time`/`end_time`。实际时间从录制推断：主录制的 `media_start_time` + `duration`（无录制时退回 `report participants` 的最早入会/最晚离会）。格式示例：`2025年10月15日 10:05-10:40`
  - **会议类型**：周期性会议写清循环规则——星期几 + 起止时间 + 循环结束日期。从 `recurring_rule`（`recurring_type`、`until_date`）+ 子会议列表推算（子会议日期间隔 7 天，按日期算出星期几）。格式示例：`周期性会议（每周一 11:00-12:00，循环至 2026-12-31）`
- 拉不到的数据如实标注「未获取」，不要编造
- 重点高亮（`==文字==`）只用于：风险、时间节点、关键决策，不要整段全亮

### 人名一律 @

纪要里每一处指人的地方都写 @：主持人、参会人员、纪要整理、摘要和会议内容里提到的人、待办责任人、风险里的人、发言统计、转写的主要发言人和每段的发言人行。

1. **查人**：把这些地方出现的姓名去重，逐个用 `list_users`（`query`＝姓名）匹配 Outline 用户，留意同名、昵称、英文名、拼音
2. **写法**：
   - 唯一匹配 → `@[姓名](mention://user/<userId>)`，姓名用 Outline 账号上的名字
   - 没有账号 → 纯文本 `@姓名`，**不能省掉 @**；后面紧跟文字时空一格
   - 「发言人N」「Rooms会议室-发言人N」这类匿名标签：确认之前原样写，不猜、不加 @
3. **写入前先问**：把没匹配上的名字、拿不准的名字（同名账号不止一个、只是相近，例如转写里的同音字「孙琪」和账号「孙七」，或只有称呼，如「王总」）、匿名发言人一次列给用户，问正确的名字、是不是外部人员。用确认后的名字写，确认结果写进基本信息的「身份确认」一行；用户也说不清的，匿名标签照原样，没有账号的写 `@姓名`
4. **转写正文是原话**：正文里说到的人名不改、不加 @，只有每段的发言人行按上面写（确认过的匿名发言人也改成 @）
5. 纪要一经创建，Outline 会给正文里提及的每个人（对这篇文档有读取权限的）发一条通知

## 四、写入 Outline

### 确定目标位置（按优先级）

1. **用户指定了文档集或项目** → 用指定的：
   - 文档集：按名字匹配 collection，找不到就按名字新建
   - 项目：用该项目下的「会议纪要」。项目是直接包含「进度与待办」的那一层（还没迁移的旧项目：直接包含「进度追踪」的那一层），可能是一篇文档，也可能是整个文档集（「进度与待办」在文档集顶层时）
   - 以下都算指定了项目：说了项目名；给了项目文档、它的「进度与待办」或「会议纪要」里任一篇文档的链接；要求归档后接着对某个项目做会后更新
   - 按项目名找到多个候选，或者指定的文档下既没有「进度与待办」也没有「进度追踪」时，列出来问用户，不要猜
2. **用户没指定** → 默认个人文档集：
   - 在 `list_collections` 里找「名字 == tmeet 的 `UserName`」的 collection
   - 没有 → `create_collection` 创建（`name` = UserName）
   - Outline 新建 collection 默认只有创建者可见，天然满足个人权限隔离，**不要**额外打开分享或添加成员
3. 目录结构（两级：会议纪要 → 会议记录，**不再建日期目录**）：
   a. 定位「会议纪要」父文档：用列集合文档树的工具（`list_collection_documents`）找标题为「会议纪要」的文档——指定了项目时找项目的直接子文档，否则找文档集顶层的；没有 → `create_document` 创建（title = 会议纪要，collectionId = 目标 collection；项目是一篇文档时再加 parentDocumentId = 项目本身那篇文档）
   a2. 项目目录的顺序（只在写到项目、并且项目有「进度与待办」时）：项目这一层固定是「看板、进度与待办、项目文档、会议纪要」排在最前面（缺的跳过，其余照这个相对顺序），其他文档在后、相互之间的顺序不动。新建了「会议纪要」（它在第 0 位）、或者用的是项目已有的「会议纪要」，都用 `list_collection_documents` 核对并修正：
      - 自上而下：对第 i 位（i＝0、1、…），应当在这一位的那篇不在，就 `move_document` 把它移到 `index: i`（项目是一篇文档时 `parentDocumentId` = 项目本身那篇文档，不是名为「项目文档」的那篇；项目是整个文档集时改传 `collectionId`、不传 `parentDocumentId`）。每次都是往上移，`index` 就是最终位置；不要把「会议纪要」直接往下移，同一个父文档里往下移时 Outline 会把 `index` 减 1
      - 例：新建后是「会议纪要、看板、进度与待办、项目文档」→ 看板移到 0、进度与待办移到 1、项目文档移到 2 →「看板、进度与待办、项目文档、会议纪要」
      - 移完再列一次核对，仍不对就再做一遍，还不对就停下、在汇报里说明。只改位置、不改内容，不需要另外确认，在汇报里说明；不为凑顺序创建别的标准文档
      - 四篇按标题逐字认；同一层有两篇同名的标准文档时不排，在汇报里列出
      - 写到默认的个人文档集、用户指定的普通文档集，或者还没迁移的旧项目（只有「进度追踪」）、迁移没做完的项目（「进度与待办」和「进度追踪」或「待办事项」并存）时，不调整顺序
      - 同一规则见 outline-promeeting-update 技能 `references/progress-doc-template.md` 第 31 条
   b. 新文档命名：`YYYY-MM-DD 会议主题`（实际开会日期 + 会议名，标题里**不写**时间段）
      - 日期 = 会议**实际**开始的日期（北京时间，来自录制起止，不是预定的 start_time）
      - 主题 = `meeting get` 的 `subject`（会议名字，如「产品周会」），不要用智能纪要的主题名（纪要是会议内容的标题，不是会议的名字）
      - 去掉「周期性会议」「周会纪要」等冗长前后缀
      - Rooms 会议室 / 个人会议号会议的 `subject` 只是会议室默认名（如「3楼会议室的个人会议室」）时，改用智能纪要的「会议主题」，压到 20 字以内；仍不合适就问用户
      - 拿不到 `subject` 时向用户询问
      - 实际起止时间写在正文的「会议时间」字段里（见第三节），排序和同名处理都从那里取开始时间
   c. 同名：「会议纪要」下已有标题相同（同日期、同主题）的文档时，先 `fetch` 它，对照正文的「会议号」和「会议时间」：
      - 是同一场会（会议号和开始时间都相同）→ 已经归档过：**不再新建，也不改它**，把已有文档的链接告诉用户。旧日期目录里（见 e）标题形如 `HH:MM-HH:MM 会议主题` 的同一场会也这样处理
      - 是另一场会 → 新文档标题后面加一个空格和实际开始时间（24 小时制），如 `2026-09-08 产品周会 16:30`；已有的那篇不改名
      - 加了时间仍然重名 → 同样先对照是不是同一场会；不是就问用户
   d. 顺序：新的在上。排序键是会议实际开始时间（标题的日期 + 「会议时间」的开始时刻；取不到开始时刻的按标题排）
      - `create_document` 会把新文档放在「会议纪要」所有子文档的**最前面**，所以按时间先后归档时不用再动
      - 补录的会议比「会议纪要」下已有的某些纪要早时：建好后调用 `move_document`（id = 新文档，parentDocumentId = 会议纪要，index 见下）把它移到比它早的纪要里最新那一篇的前面
      - `index` 取法：在 `list_collection_documents` 返回的当前顺序里（从 0 数起，新文档自己在第 0 位，也要算上），它应当排到哪一篇前面，就传那一篇现在的位置。例：当前顺序是「新文档、9/15、9/08、9/01」，新文档是 9/10 的会，应排在 9/08 前面，9/08 现在在第 2 位，就传 `index: 2`，移完是「9/15、新文档、9/08、9/01」。它比所有同级文档都早时不传 `index`，会被放到最后。原因：在同一个父文档里往下移时，Outline 按移动前的顺序理解 `index`，传「比它新的篇数」会少移一位（只有一篇比它新时等于没动）
      - 旧日期目录（见 e）也是同级文档：按目录标题的日期排，同一天的纪要排在日期目录前面
      - 移完用 `list_collection_documents` 核对「会议纪要」下的顺序，不对就再用 `move_document` 调整
      - `fetch` 目标文档集，返回的 `sort.field` 不是 `index`（文档集不是手动排序）时，侧栏按标题排序、不看 `index`；标题开头的日期仍然让纪要按日期排，只是方向由文档集的设置决定。不要为此改动文档集，在汇报里提一句即可
   e. 旧的日期目录：「会议纪要」下还有以前按日期建的目录（标题 `YYYY-MM-DD`，里面是 `HH:MM-HH:MM 会议主题`）时，新纪要照样直接放在「会议纪要」下，不再往日期目录里放；旧目录和里面的纪要**不移动、不改名**。在汇报里提示：旧纪要可以按 outline-promeeting-update 技能 `references/migration.md` 的「会议纪要一层化」迁出，需要用户同意，本技能不自行移动
4. 文档头部的「会议主题」字段：只写智能纪要给出的主题名（不要拼接 `subject` 前缀）

### 创建文档

- `create_document`：
  - `title` = 上述命名（`YYYY-MM-DD 会议主题`，同名时带「 HH:MM」）
  - `parentDocumentId` = 「会议纪要」文档 ID（新文档直接作为它的子文档，中间没有日期目录）
  - `text` = 组装好的 markdown，`format` = markdown
- 写入前自检，有一项不通过就先改：
  - 每一处人名都是提及或纯文本 `@姓名`（转写正文里的原话、没确认的匿名标签除外）
  - 没匹配上、拿不准的名字都已经问过用户，确认结果写进了「身份确认」
  - 基本信息有「纪要整理」一行：current_user 的提及 · 整理时间（YYYY-MM-DD HH:MM，北京时间）· 来源
- 补录较早的会议时按上面 d 用 `move_document` 排位，并用 `list_collection_documents` 核对
- 写入后重新 `fetch`，核对提及仍是提及（`mention://` 链接），没有渲染出来的在汇报里说明
- 完成后汇报给用户：
  - 文档链接和位置，如 `产品研发 › 会议纪要 › 2026-09-15 产品周会`
  - 标题加了「 HH:MM」、按同一场会跳过了新建、或补录后调整了位置时，说明一句
  - 按 a2 调整了项目目录的顺序时，说明移了哪几篇、移完的顺序
  - 文档集不是手动排序（d 的最后一条）、「会议纪要」下还有旧日期目录（e）时，按上面的说法提示
  - 纪要整理人；用户确认过的身份；没有 Outline 账号、写成 `@姓名` 的人

## 五、规范与安全

- 严禁向用户展示 `meeting_id`，一律用 `meeting_code`（会议号）
- 严禁输出 AccessToken / RefreshToken / Outline token
- 破坏性写操作前先向用户确认：取消/修改会议、删除/移动 Outline 文档、修改文档集成员（本技能刚创建的纪要在「会议纪要」内按时间排位、按第四节 a2 调整项目目录的顺序不算，见第四节 a2、d）
- 不修改已有纪要的正文；纪要的标题和位置只在按迁移方法一层化、并经用户同意时调整。纪要建好后的编辑，由 outline-promeeting-update 记在会议子文档页首（纪要的创建人、最后编辑人和时间）
- 不再创建日期目录，也不往旧日期目录里放新纪要
- tmeet 通讯录查询仅限"会议邀请 / 呼叫入会"的前置场景
- 转写内容可能含敏感信息，写入前提醒用户确认目标文档集的可见范围
